Module Structure

Every workflow module follows this structure:

"""
ModuleName Workflow Procedure Module
"""

## version related
__author__ = "your name"
__version__ = "0.0.2"
__email__ = "your@email.com"

## import buildin pkgs


class ModuleName(object):
    def __init__(self, logger: object) -> None:
        self.logger = logger

    def your_method(self, context: dict, cfgs: dict) -> dict:
        """
        Description of what this method does.

        Args:
            param1 (str): Description of param1
            param2 (int): Optional — description of param2

        Returns:
            dict: Result with status key
        """

        ## load args
        param1 = cfgs.get('param1', '')

        ## debug prt
        self.logger.debug({'param1': param1})

        try:
            ## your logic here
            result = param1

            return {
                'status': True,
                'data': result
            }

        ## error handling
        except Exception as e:
            self.logger.error({'status': 'Error: %s' % (e)})
            return {
                'status': False
            }
Key Conventions
Class name PascalCase, must match filename (e.g. MyModule.py → class MyModule)
Method signature def method(self, context: dict, cfgs: dict) -> dict
Parameters Read from cfgs.get('key', default). Document in Args: docstring section.
Return value Always return {'status': True/False, ...}. Add data as extra keys.
Comments Use ## prefix (double hash). Sections: load args, debug prt, error handling.
Error handling Wrap logic in try/except. Always self.logger.error({'status': 'Error: %s' % (e)}).
Docstrings Google-style with Args: and Returns: sections for auto-introspection.
Context dict Shared data between steps. Reference prior steps via @step_name or @step.key.
Supported Arg Types

Use these types in your docstrings for the visual editor to render correct input fields:

str → text input int → number input bool → checkbox dict → JSON editor list → JSON editor
